# Deploy to Render (free)

You'll create two services from `render.yaml`:

- `code-quest-api`: Spring Boot in Docker (free web service, sleeps when idle)
- `code-quest-web`: the React build as a static site (free, always on)

## 0. Before you start

- Code is pushed to GitHub (`logeshvz67-svg/InterviewPrep`).
- Supabase is set up and you have the three `DATABASE_*` values (see `SETUP_SUPABASE.md`).

## 1. Create the services from the Blueprint

1. https://render.com → sign up with GitHub (no card needed for free services).
2. **New → Blueprint** → connect the `InterviewPrep` repo → Render reads `render.yaml`.
3. Render asks for every variable marked `sync: false`. Fill them in:

| Service | Key | Value |
|---|---|---|
| api | `DATABASE_URL` | `jdbc:postgresql://<pooler-host>:5432/postgres?sslmode=require` |
| api | `DATABASE_USERNAME` | `postgres.<project-ref>` |
| api | `DATABASE_PASSWORD` | your Supabase DB password |
| api | `ADMIN_EMAILS` | the email you'll register with |
| api | `CORS_ALLOWED_ORIGINS` | `https://code-quest-web.onrender.com` (your static site URL; fix it later if the name differs) |
| api | `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `OPENROUTER_FALLBACK_MODELS` | leave **empty** until Phase 3 |
| web | `VITE_API_URL` | `https://code-quest-api.onrender.com` (your API URL, no trailing slash) |

`JWT_SECRET` is generated by Render automatically (`generateValue: true`).

4. Click **Apply**. The first Docker build takes ~5-8 minutes (Maven downloads dependencies).

## 2. Check it

- Open `https://code-quest-api.onrender.com/health` → `{"status":"UP"}`
- Open `https://code-quest-api.onrender.com/swagger-ui.html` → API docs
- Open `https://code-quest-web.onrender.com` → the wake screen, then the login page

If the service names were taken and Render gave you different URLs, update `CORS_ALLOWED_ORIGINS` (api) and `VITE_API_URL` (web), then redeploy both. **The static site must be rebuilt after changing `VITE_API_URL`**, because Vite bakes it into the JavaScript at build time.

## 3. Lock it down (single user)

1. Register your account in the app (your `ADMIN_EMAILS` address becomes ADMIN).
2. Render → `code-quest-api` → Environment → set `REGISTRATION_ENABLED=false` → Save (it redeploys).
   Now nobody else can create an account.

## 4. Why the Dockerfile looks like this

- **Multi-stage build**: stage 1 has Maven + JDK to build; stage 2 is a small JRE image, so the final image is smaller and starts faster.
- **JVM flags for 512 MB RAM**: `-Xmx256m` caps the heap and leaves room for metaspace, threads and the OS. `-XX:+UseSerialGC` is the lightest garbage collector. `-XX:TieredStopAtLevel=1` speeds up startup, which matters for cold starts.
- **Runs as a non-root user**: basic container hygiene.
- **`$PORT`**: Render tells the app which port to use; `application.yml` reads it.

## 5. Cold starts

The free API sleeps after ~15 minutes without traffic. The next visit takes ~30-60 s while the container and the JVM start. The frontend handles this with:

- A friendly **"Waking the server…"** screen that pings `/health` every 3 s (up to 2 minutes).
- Automatic retries with backoff on network errors and 502/503/504 for normal API calls.
- No server-side timers: Pomodoro end times, streaks and quests are all computed from timestamps stored in the database, so a sleeping server loses nothing.

To avoid cold starts altogether, see `UPTIMEROBOT.md`.

## 6. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Deploy fails with `Connection refused` / `UnknownHost` | Wrong `DATABASE_URL` or you used the direct (IPv6) host | Use the **Session pooler** host, port 5432, with the `jdbc:` prefix |
| `password authentication failed` | Username missing `.project-ref` | `DATABASE_USERNAME=postgres.<project-ref>` |
| App starts then crashes with `JWT_SECRET must be at least 32 characters` | Secret too short | Use `generateValue` or `openssl rand -base64 48` |
| Browser console: CORS error | `CORS_ALLOWED_ORIGINS` doesn't exactly match the static site URL | No trailing slash, https, exact sub-domain |
| Login works, then 404 on page refresh | SPA rewrite missing | The `routes: rewrite /* → /index.html` in `render.yaml` handles it; check the static site's Redirects/Rewrites tab |
| Out of memory / restarts | Heap too big | Keep `-Xmx256m`; don't raise the Hikari pool |
